# id-000 — IDQ index

The IDQ holds the project's concrete open problems, one file per problem (`id-NNN`), each saying
what is wrong, why it matters, and what would close it. Milestones and coverage live in the
[roadmap](../roadmap.md) (`li-NNNN`); work toward a problem is done in ops (`op-NNN`, via
`tools/rob`). One problem may be served by several ops, each for one agent. Terms:
[terminology.md](../terminology.md) §6.

**Choosing work (Coordinator, 2026-07-11):** pick from live, preview-relevant IDQ problems. The
roadmap supplies the coverage bar and ordering; it is not a queue of subsystem audits. A consult
finding must bind to an existing live IDQ, or justify a new one, before any follow-on op is
written. Closed or dropped ids are never reused as parents.

`id-NNN` is zero-padded, sequential, never reused. `id-000` is this index.

## States

| state | meaning |
|---|---|
| **WAITING** | preconditions unmet; names what it waits on (a Coordinator decision or an op). |
| **READY** | preconditions met; ops can be written now. |
| **IN WORK → op-NNN** | one or more ops serve it; the row names them. |
| **DEFERRED** | parked past a named milestone (for example post-1.0-preview). |
| **CLOSED** | the problem is resolved on first-hand evidence. |
| **DROPPED** | abandoned or found to be a false premise; the row says why. |

Older rows use **FETCHED** for IN WORK and **RETIRED** for CLOSED; read them the same way.

## Maintenance

Add a row when an `id-NNN` is raised and update its state as it moves. When ops start serving
it, name them in both this row and the entry file. Priority is high (on the preview critical path or a preview blocker), medium (needed for the
preview but not blocking now), low (post-preview or hygiene), or — (closed or dropped); the
Coordinator sets it. Keep this index terse: one row per problem;
detail lives in the entry file.
