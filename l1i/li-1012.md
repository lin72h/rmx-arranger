# li-1012 — clean-provenance x86-64-v3 DEFAULT baseline + full-component re-validation (do-it-once, do-it-right)

li-1012 | tier: L1i | milestone 1 (1.0-preview) constituent | status: ACTIVE (design — op stream gated on op-149 result) | owner: Coordinator 2026-06-27 (designed by the Arranger seat, model Opus 4)

## WHAT IT MEANS

Make **x86-64-v3 the DEFAULT build** of rmxOS — base, kernel, and (li-1009 P2) ports/pkg — but do it on a
foundation we have never actually had: a **clean-object, from-scratch buildworld of the CURRENT source HEAD**,
with the accumulated baseline-buildability debt paid down, and then **re-confirm every core component on that
clean-provenance image** before the default flips. Take the time to do it once, elegantly, correctly.

## WHY (the discovery that birthed this li — 2026-06-27)

The op-149 v3 tryout, by building from a FRESH object prefix to isolate the v3 flags, forced the **first true
clean-obj buildworld this tree has ever had on this host** — and it kept hitting walls (iconv header
self-containedness → `libsys.so.7` objcopy/strip → sys/mach header install). First-hand finding:

- The "alpha tree builds the image perfectly" belief rested on host-level **incremental** object caches
  (`/Users/me/wip-mach/build/{wip-rmxos-alpha-obj, block-075-alpha-*-obj}`) that contain **no `libsys` at all**
  — they predate the FreeBSD **libsys split** the tree has since absorbed (`libsys: relocate implementations`,
  `libc/sys/Makefile.inc -> libsys/Makefile.sys`). So "it built before" was an OLDER, pre-libsys tree built
  incrementally — NOT the current HEAD. The walls aren't from the 2 v3 lines and aren't from the wrong tree;
  they are **pre-existing structural debt the incremental caches were masking.**
- Consequence (the load-bearing one): every prior conformance/soak result — asl legs, notifyd, libxpc, etc. —
  ran against images of **uncertain build-provenance** (likely incremental, possibly stale relative to HEAD).
  That does NOT make them *invalid* (the binaries really ran and behaved as recorded), but it makes them
  **provisionally green, pending re-confirmation on a clean-provenance image.** A SOURCE fix (e.g. id-025
  notifyd wait-path) is the sharp risk: an incremental image may not contain the object the fix touched.

## THE PROVENANCE PRINCIPLE (the spine of this li)

A test result is only as trustworthy as the build-provenance of the binary it exercised. Henceforth the
canonical artifact is a **clean-obj buildworld of a named source SHA**, content-verified (mount + `readelf`
the actual binary — never trust filename/size; `feedback_artifact_identity_needs_content_check`). Incremental
images are fine for fast iteration but are NOT admissible as truly-green evidence. "Stale ≠ wrong, but stale ≠
confirmed."

## TRULY-GREEN BAR (what "done" means for li-1012)

1. **Clean baseline exists:** a from-scratch `buildworld`+`buildkernel` of current HEAD completes with NO
   ad-hoc/host-binary workarounds (no `OBJCOPY=/usr/bin/...` swaps) — every wall cleared by a faithful,
   committed fix. The baseline-buildability debt (libsys + header staging) is retired in-tree.
2. **v3 layered on the clean baseline:** the same clean build at `CPUTYPE?=x86-64-v3` + `COPTFLAGS=-O2 -pipe`
   is build-clean, boot-clean, kernel verified NOT emitting in-kernel AVX/SSE (the one true correctness risk),
   v3 codegen confirmed present in userland (li-1009 steps 3-5).
3. **Stability soak holds** on the v3 clean image (op-168 adoption gate: SIGILL-free, no FPU-fault/panic, no
   miscompile signature, li-1001 invariants flat on the v3 kernel).
4. **Every core component RE-CONFIRMED on the clean-provenance v3 image** — re-confirm, NOT re-derive: the
   conformance *logic* is already proven; we confirm it reproduces on a clean-built binary. Components to
   exercise: **{launchd, notifyd/libnotify, asl, libxpc}** (the 4 core services) + **libdispatch** + the
   **li-1001 mach substrate invariants**. Source-fix-dependent legs (id-025 notifyd) verified FIRST.
5. **Default flipped:** v3 + `-O2 -pipe` adopted as the default rmxOS build baseline (no-legacy / pre-Haswell
   unsupported stance documented) — Coordinator's adoption call, on the evidence of 1-4.

## PHASES

- **P0 — clean baseline (Implementer).** Drive the current HEAD to its first clean-obj buildworld; faithful
  fixes only; retire the libsys/staging debt. *This is op-149's current run* — its result (clean image, or the
  remaining wall list) is the gate that unlocks the rest of this li. (op-171 is the elegance sub-pass: ensure
  the toolchain wall is faithfully resolved, not host-binary-swapped.)
- **P1 — v3 correctness on the clean baseline (Implementer).** li-1009 steps 3-5 on the clean image
  (kernel-AVX safety, codegen sanity, userland smoke).
- **P1-soak — v3 stability (Gatekeeper).** op-168 adoption-gate soak on the clean v3 image.
- **P2 — full-component re-validation (Gatekeeper + Explorer authoring).** Re-confirm each core component on
  the clean-provenance v3 image, source-fix-dependent legs first (id-025 notifyd). Each leg: content-verify
  the binary's provenance, then re-run the established conformance/soak bar; PASS = reproduces on clean
  provenance. This is the bulk of the op stream (one re-validation op per component/leg).
- **P3 — default switch (Coordinator).** On P1-soak hold-stable + P2 all-reconfirmed, flip v3 to the default;
  document the no-legacy stance. Folds li-1009 P2 (ports/pkg at v3) + P3 (default the image) into the
  clean-provenance discipline.

## OPEN VERIFY (do not assert as fact yet)

- **libsys = relocation-not-behavior** is an ASSUMPTION doing real work in "stale ≠ wrong." The syscall-stub
  relocation is *expected* behavior-neutral, but per `feedback_verify_signature_divergence_claims` this must be
  CONFIRMED on the clean image (diff behavior of a pre-libsys vs post-libsys binary on a syscall path), not
  taken on faith, before P2 reuses any prior green as a shortcut.
- The exact staleness of existing soak images (op162-leg2, the notifyd image) — do they contain post-libsys
  binaries? — sizes the P2 re-validation job; a cheap content-check (readelf for `libsys` linkage) up front.
