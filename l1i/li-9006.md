## WHAT IT MEANS

Zig should take the architectural lesson from Swift PR #90000—**one canonicalization boundary**—
without copying Swift's raw numeric priority scheme. Zig does not yet expose a portable task-
priority contract, so rmxOS can start with a clean semantic API:

```text
Zig WorkClass
  → one named semantic-to-Dispatch canonicalization boundary
  → five canonical Dispatch QoS queues
  → rmxOS libdispatch
  → pthread_workqueue / TWQ admission
  → ordinary FreeBSD ULE worker threads
```

The initial type is deliberately small and non-numeric:

```zig
pub const WorkClass = enum {
    inherit,
    background,
    utility,
    default,
    user_initiated,
    user_interactive,
};
```

The five concrete cases map by **name and meaning** onto five Dispatch QoS queues. `.inherit`
remains distinct from `.default`: it means use the caller-provided/ambient target-queue contract,
not “silently choose default.” If a future Zig API exposes arbitrary numeric priorities, every
value must be canonicalized once into these five concrete classes—never one queue per raw value.

Keep four domains visibly separate:

1. Zig semantic `WorkClass`;
2. named `dispatch_qos_class_t`;
3. legacy Dispatch queue priorities;
4. encoded `pthread_priority_t` / TWQ lane values.

No public Zig enum receives Dispatch's numeric constants, and no numeric Swift `TaskPriority`
crosses the Zig ABI.

### Concrete limitations that constrain the pilot

- `Io/Dispatch.zig:454-469` wires the network operation family to `*Unavailable` functions.
  Network behavior is outside the initial acceptance claim.
- `Io/Dispatch.zig:190-207` sets `min_stack_size = 60 * 1024 * 1024` and includes it in each
  Fiber allocation. The pilot must measure roughly 60 MiB-plus per live fiber rather than treating
  this snapshot as production-scalable.
- Dispatch sources/timers repeatedly call `object.activate()` (including the central pending-task
  path at `Io/Dispatch.zig:656-657` and timer/source paths throughout the file).
- Zig's pinned Darwin binding defines legacy `queue_priority_t.LOW = -1`
  (`lib/std/c/darwin/dispatch.zig:71-75`), while native rmxOS declares
  `DISPATCH_QUEUE_PRIORITY_LOW = -2` (`lib/libdispatch/dispatch/queue.h:356-359`). This is direct
  evidence that copied magic numbers are unsafe; the rmxOS package must derive named bindings from
  the headers it actually links.

### rmxOS substrate

The same first-hand rmxOS source census recorded in li-9005 applies:

- native libdispatch accepts named QoS attributes and passes encoded root-queue priority to the
  libthr TWQ path;
- libthr and the kernel distinguish TWQ admission lanes;
- current-thread QoS getters/setters and priority overrides remain stubs, so this is not yet
  macOS-equivalent CPU priority, donation, or escalation;
- native classic libdispatch has `dispatch_resume()` but no `dispatch_activate` symbol.

The missing `dispatch_activate` ABI is shared with li-9005 and must be closed **once** in native
rmxOS libdispatch. Do not create competing Swift-only and Zig-only product shims.

## ARCHITECTURE CONTRACT

### One canonical queue set

The integration layer owns at most five concrete QoS queue targets per process/integration domain.
A fixed-class `rmx.Io.Dispatch` instance targets one of them. `.inherit` consumes an explicitly
supplied target/ambient contract and never creates a sixth “inherit” QoS class.

Creating a child concurrent queue per `Io.Dispatch` instance is consistent with upstream; creating
one target queue per arbitrary raw priority is not. Zig submits through libdispatch and shares the
hosting process's native worker population with its C/Swift/XPC-facing dispatch consumers. This is
process-local; it does not imply worker-thread sharing between separate service processes.

### Generated bindings, not copied Darwin constants

The preview-safe package supplies rmxOS-native Dispatch/CoRT bindings generated from or checked
against the exact product headers. It uses named QoS values and `_f` callback APIs. The legacy
`LOW` mismatch is a required negative fixture proving that the package does not import Darwin
magic numbers accidentally.

`CoRT-lite` here means thin Zig lifetime wrappers over the existing libdispatch/`os_object`
retain/release ABI. It does **not** mean a new `libcort`, a relocated object runtime, or an
Objective-C dependency.

At minimum the package distinguishes:

- `OwnedQueue`: owns a balanced reference and releases it exactly once; and
- `BorrowedQueue`: never releases the caller's reference and is valid only for its documented
  lifetime.

Before asynchronous use crosses the caller's borrow lifetime, the bridge must take and later drop
a balanced Dispatch reference. The pilot must verify whether the child queue's target relationship
retains the target and prove the resulting ownership graph; do not infer this from type names.

### Swift–Zig bridge

The preferred ABI passes a borrowed `dispatch_queue_t` from Swift/C into Zig with an explicit
lifetime contract. Zig then initializes its fixed-class `Io.Dispatch` against that target. No
`TaskPriority.rawValue` crosses the ABI.

If a semantic enum must cross instead, expose a small C ABI enum with only
`inherit/background/utility/default/user-initiated/user-interactive`, validate every value, and
canonicalize at the queue factory. Do not expose Dispatch or pthread numeric encodings as the Zig
API.

### Process-wide workqueue ownership

Zig must never initialize or drive `_pthread_workqueue`/TWQ directly. Native libdispatch is the
process-wide owner; Zig submits queues and function callbacks through it. One process loads one
libdispatch implementation.

## PHASED EXECUTION LADDER

### P0 — rmxOS Dispatch package + ABI/lifetime closure

- Produce the generated/verified rmxOS Dispatch bindings, restricted initially to named QoS,
  `_f` callbacks, queue/source/semaphore/time APIs, and CoRT retain/release.
- Implement/test `OwnedQueue` and `BorrowedQueue` contracts without ObjC or Blocks.
- Consume the shared native `dispatch_activate` closure from li-9005; prove source/timer activation
  rather than substituting `dispatch_resume` by assumption.
- Pin Zig source identity and compile against the exact rmxOS headers/libraries.

### P1 — fixed-class `rmx.Io.Dispatch` pilot

- Instantiate one `Io.Dispatch` against one selected canonical queue; run all five concrete classes
  and `.inherit` as separate cases.
- Do not fork the evolving `Io.VTable` and do not add per-operation priority.
- Exercise Future/Group, async/concurrent work, timer/sleep, cancellation, mutex/futex, and clean
  shutdown. Treat unsupported network operations as expected negative cases, not green coverage.
- Measure one/two/N-fiber resident and virtual memory; set a fail-closed laboratory ceiling around
  the current 60 MiB-plus allocation per fiber.

### P2 — Swift/C host → Zig borrowed-queue bridge

- Pass a named canonical queue handle, not a raw priority.
- Prove balanced retain/release, host teardown, Zig cancellation, and late callback behavior under
  sanitizers/diagnostics available on the platform.
- Run multiple Zig instances targeting the same queue and different classes; prove they share
  libdispatch/TWQ rather than creating a second scheduler.

### P3 — differential Dispatch/TWQ conformance workload

Run the same Zig Future/Group/timer/cancellation program against Apple Dispatch and rmxOS Dispatch.
Compare only observable contracts supported on both platforms, then retain rmxOS
`LIBPTHREAD_TWQ_TRACE` evidence for class→encoded priority→lane/bucket.

Repository/role split is mandatory:

- **Explorer** authors the differential conformance content in `rmx-explorer`.
- **Gatekeeper** separately parks/registers/runs it in `rmx-gatekeeper`; one op never writes both
  repositories.
- **Implementer** alone changes native rmxOS libdispatch/libthr/kernel product source.
- The Coordinator must name the Zig-side executor and writable package repository before a Zig
  package/build op is issued; `/Users/me/wip-mach/nx/zig-master` remains a read-only upstream
  source checkout.
- L/XL returned gates go to a Validator under Rule 11; the Arranger retains retirement authority.

### P4 — per-operation priority, escalation, and donation (later)

Do not add this to the initial pilot. A correct per-operation class must survive every fiber resume,
timer/source wakeup, mutex/futex wait, cancellation, group operation, and child task—not only the
first enqueue. Await-driven escalation/donation and inversion handling depend on the real thread-
QoS work in li-9005/li-9003 Item 4 and require a separate design and evidence gate.

## TRULY-GREEN BARS

### P0/P1 — fixed-class pilot green

1. Zig tag/commit, generated binding inputs, rmxOS headers/libraries, product/image, and actual
   dispatch engine are pinned.
2. The binding uses named QoS classes; a test catches the `LOW=-1` vs `LOW=-2` mismatch instead of
   propagating it.
3. All five concrete `WorkClass` values select the intended queue and TWQ lane; `.inherit` remains
   observably distinct from forced default.
4. Future/Group/timer/cancellation paths complete; `dispatch_activate` is genuinely present and
   exercised.
5. Queue ownership survives teardown with balanced references and no late-callback use-after-free.
6. Memory is measured across fiber counts and judged against an explicit laboratory ceiling.
7. Unsupported networking fails closed and is not counted as covered.
8. FreeBSD's default `Io.Evented = Kqueue` selection remains unchanged.

### Full track — shared-scheduler integration green

In addition to P0/P1, the Swift/C borrowed-queue bridge passes lifetime and teardown tests; the
Apple/rmxOS differential workload matches the supported observable contract; and TWQ traces prove
all five lanes on the actual engine. Per-operation priority, CPU scheduling, donation, or
inversion-avoidance claims require their later dedicated gate.

## BOUNDARIES / DEFAULT DISPOSITION

- **Milestone-9, non-gating by default.** The typed package, fixed-class pilot, and differential
  suite are architecturally preview-safe candidates, but do not become li-1000 work without an
  explicit Coordinator scope/placement decision.
- **Post-preview:** making `std.Io.Dispatch` the FreeBSD default, changing upstream `Io.VTable`,
  dynamic per-task priority, or cooperative/task-stealing behavior.
- **Do not switch all FreeBSD Zig programs to Dispatch.** Preserve upstream Kqueue selection.
- **No raw-priority queue explosion, no magic constants, no direct TWQ ownership, no ObjC/Blocks
  requirement, and no second libdispatch.**
- **id-039 is now authored as a WAITING design seed.** It banks the corrected audit-first
  decomposition only and authorizes no package/product implementation or ROB op.
