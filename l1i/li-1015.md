# li-1015 — rmxOS on real x86 hardware: a bootable disk image, then an installer

li-1015 | tier: L1i | milestone 1 (1.0-preview) constituent | priority: **high** (Coordinator,

## Goal

rmxOS runs on a real x86-64 machine, not only in bhyve: first from a disk image written straight to
a USB stick or disk, then installed by an installer (`bsdinstall` memstick/ISO, the id-012 track).

## Gate (Coordinator, 2026-10-08: "I don't want to deal with kernel panics on real hardware")

Do not start until both hold, each on first-hand evidence:
1. **Core kernel ready:** the Mach foundation round is closed — id-046 fixes accepted, id-061
   closed, the Mach review remainder (id-052) and the blind review round 2 (id-051) done with their
   findings fixed or recorded as known 1.0 gaps, CI running the Mach suite on every candidate
   (id-047), and a clean KASAN run of the suite on the candidate.
2. **Core libraries ready:** libdispatch, launchd (PID 1), libxpc, libnotify and asl through their
   review-and-fix round (now.md step 4: op-384, op-385, op-386 and libdispatch's deep review) with
   no open high-priority defect.

Progress on gate 1 (2026-10-09): first clean KASAN run of the full suite on `mach-fixes-6@13628bbe` (93/93, MIG 5/5, repeat 400/400, no KASAN report; op-567, verified j-20261009-001); RELEASE of the same commit proven by op-581. ## State at opening (2026-10-08, from the source and images)

Ready:
- The world and kernel build from source (alpha2; op-436 rebuilt both).
- RMXOS-RELEASE includes `GENERIC` (via MACHDEBUG), so FreeBSD's hardware drivers are present.
- The images boot in bhyve with a ZFS root, launchd as PID 1, getty and base services (op-436,
  op-470); `loader.efi`, `boot1.efi`, `gptboot.efi` and `zfs.ko` are in the image.

Missing:
1. Boot layout: images are GPT with only a `freebsd-zfs` partition and boot through `bhyveload`;
   hardware needs an EFI system partition with `loader.efi` and a `freebsd-boot` partition for BIOS.
2. Console: serial only so far; hardware needs `vt` (screen and keyboard) with serial as fallback.
3. Network and system configuration under launchd as PID 1 (DHCP on a real NIC) never tested.
4. CPU floor: the index records alpha2 as built with `-march=x86-64-v3` (AVX2; Haswell / Excavator
   or newer) — to verify in the build before choosing a machine.
5. The kernel carries debug options (`std.debug`, INVARIANTS, WITNESS, DEBUG_LOCKS): acceptable for
   a developer machine, slower; decide before the installer stage.

## Plan once the gate holds

1. **Hardware image (Implementer, one op):** from the accepted candidate; GPT with ESP + BIOS boot +
   ZFS root, `vt` and serial console, DHCP; first booted in bhyve in UEFI mode to prove the EFI path.
2. **First boot on the machine (Coordinator):** `dd` to USB or a spare disk; a checklist (boot log,
   devices, launchd jobs, network, clean shutdown, the Mach suite on hardware). This is the B0
   baseline of the installed-machine track (Coordinator's split, 2026-10-07).
3. **Installer (id-012):** `bsdinstall` memstick/ISO through FreeBSD's `release/` pipeline, ZFS root
   by its `zfsboot` flow.

Needed from the Coordinator before step 1: the machine's CPU model, UEFI or BIOS, target disk,
network card, and whether it has a serial port.
